# 🔒 Политика безопасности

Политика безопасности репозитория **Bjorn** включает все необходимые меры по обеспечению безопасности.

## 🧮 Поддерживаемые версии

Мы предоставляем обновления безопасности для следующих версий проекта:

| Версия  | Статус              | Безопасна |
| ------- | ------------------- | --------- |
| 1.3.x   | Поддерживается      | ✅ Да      |
| ≤ 1.2.x | Не поддерживается   | ❌ Нет (нет Basic Auth на веб-интерфейсе) |

## 🛡️ Меры безопасности

- Мы следуем лучшим практикам безопасного кодирования и управления инфраструктурой.
- Проводятся регулярные аудиты безопасности и ревью кода для выявления и устранения потенциальных рисков.
- Зависимости отслеживаются и обновляются для устранения известных уязвимостей.

## 🔐 Веб-интерфейс (WEB-8 / WEB-4)

Веб-интерфейс на порту `8000` защищён **HTTP Basic Auth** (с версии v1.3.0).

### Учётные данные по умолчанию

- **Логин:** `admin`
- **Пароль:** `bjorn`

При запуске с паролем по умолчанию сервис записывает в журнал
предупреждение и призывает сменить пароль перед выставлением устройства
в локальную сеть.

### Управление аутентификацией

Все ключи хранятся в `config/shared_config.json` и редактируются через
страницу конфигурации веб-интерфейса:

| Ключ                | По умолчанию | Назначение                                              |
| ------------------- | ------------ | ------------------------------------------------------ |
| `web_auth_enabled`  | `true`       | Включить/выключить Basic Auth                          |
| `web_username`      | `admin`      | Имя пользователя                                       |
| `web_password`      | `bjorn`      | Пароль — **смените перед deploy в неконтролируемой LAN** |
| `web_bind_address`  | `0.0.0.0`    | Адрес привязки; `127.0.0.1` для доступа только с хоста |

> **Смените пароль по умолчанию.** Basic Auth не имеет принудительного
> механизма смены — ответственность лежит на администраторе. Пароль хранится
> в `shared_config.json` в открытом виде, права на чтение только у root/bjorn.

### Security-заголовки

Каждый ответ автоматически несёт (WEB-4):

- `Content-Security-Policy: default-src 'self' 'unsafe-inline'; img-src 'self' data:;`
- `X-Frame-Options: DENY` (защита от clickjacking)
- `X-Content-Type-Options: nosniff` (защита от MIME-sniffing)

### CSRF-защита

Все `POST`-запросы требуют заголовок `X-CSRF-Token`, значение которого
выдаётся эндпоинтом `/csrf_token` и сравнивается с `shared_data.csrf_token`.
Запросы без валидного токена отклоняются с `403`.

## 📲 Обновления безопасности

- Обновления безопасности выпускаются как можно скорее после подтверждения уязвимости.
- Пользователям рекомендуется обновляться до последней версии для получения исправлений безопасности.

## 🚨 Сообщение об уязвимости

Если вы обнаружили уязвимость безопасности в этом проекте, выполните следующие шаги:

1. **Не создавайте публичный issue.** Свяжитесь с нами напрямую для ответственного раскрытия уязвимости.

2. **Отправьте email** на [bjorn-cyberviking@outlook.com](mailto:bjorn-cyberviking@outlook.com) со следующей информацией:

   - Описание уязвимости.
   - Шаги для воспроизведения проблемы.
   - Потенциальное влияние или степень серьёзности.

3. **Дождитесь ответа.** Мы подтвердим получение вашего сообщения и оперативно устраним проблему.

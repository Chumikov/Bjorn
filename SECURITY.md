# 🔒 Политика безопасности

Политика безопасности репозитория **Bjorn** включает все необходимые меры по обеспечению безопасности.

## 🧮 Поддерживаемые версии

Мы предоставляем обновления безопасности для следующих версий проекта:

| Версия  | Статус              | Безопасна |
| ------- | ------------------- | --------- |
| 1.5.x   | Поддерживается      | ✅ Да (login + HMAC-сессии + salted hash) |
| 1.4.x   | Поддерживается      | ✅ Да (login + HMAC-сессии + salted hash) |
| 1.3.x   | Поддерживается      | ✅ Да (HTTP Basic Auth) |
| ≤ 1.2.x | Не поддерживается   | ❌ Нет (нет аутентификации на веб-интерфейсе) |

## 🛡️ Меры безопасности

- Мы следуем лучшим практикам безопасного кодирования и управления инфраструктурой.
- Проводятся регулярные аудиты безопасности и ревью кода для выявления и устранения потенциальных рисков.
- Зависимости отслеживаются и обновляются для устранения известных уязвимостей.

## 🔐 Веб-интерфейс (WEB-8 / PORT-8 / WEB-4)

Начиная с **v1.4.0** вход в веб-интерфейс — через **страницу логина** с
**HMAC-подписанными сессионными cookie**; пароль хранится **salted+hashed**
(PBKDF2-SHA256). В v1.3.x использовался HTTP Basic Auth (браузерный диалог);
Basic сохранён как fallback для curl/API-клиентов.

### Учётные данные по умолчанию

- **Логин:** `admin`
- **Пароль:** `bjorn`

При запуске с паролем по умолчанию сервис записывает в журнал предупреждение
и призывает сменить пароль перед выставлением устройства в локальную сеть.

### Управление аутентификацией

Ключи хранятся в `config/shared_config.json` и редактируются через страницу
конфигурации:

| Ключ                | По умолчанию | Назначение                                              |
| ------------------- | ------------ | ------------------------------------------------------ |
| `web_auth_enabled`  | `true`       | Включить/выключить аутентификацию                      |
| `web_username`      | `admin`      | Имя пользователя                                       |
| `web_password_hash` | (мигрируется)| PBKDF2-SHA256 hash пароля (PORT-8)                      |
| `web_password_salt` | (мигрируется)| Соль к хэшу (PORT-8)                                    |
| `web_bind_address`  | `0.0.0.0`    | Адрес привязки; `127.0.0.1` для доступа только с хоста |

> **Смените пароль по умолчанию.** При первом входе plaintext-`web_password`
> автоматически мигрируется в `web_password_hash`+`web_password_salt` (plain
> удаляется). Сессия — cookie `bjorn_session` (`HttpOnly`; `SameSite=Strict`),
> отзыв через `/logout`. Basic Auth по-прежнему принимает `admin:bjorn` для
> curl/API.

#### Смена пароля

1. Отредактируйте `config/shared_config.json`: установите `"web_password": "<новый пароль>"`.
2. Перезапустите сервис: `sudo systemctl restart bjorn.service`.
3. При первом запросе новый пароль автоматически перехэшируется (старый hash заменяется).

> Не редактируйте `web_password_hash` / `web_password_salt` напрямую —
> установка `web_password` (plaintext) — единственный правильный способ.

### Security-заголовки

Каждый ответ автоматически несёт (WEB-4):

- `Content-Security-Policy: default-src 'self' 'unsafe-inline'; img-src 'self' data:;`
- `X-Frame-Options: DENY` (защита от clickjacking)
- `X-Content-Type-Options: nosniff` (защита от MIME-sniffing)

### CSRF-защита

Все `POST`-запросы требуют заголовок `X-CSRF-Token`, значение которого
выдаётся эндпоинтом `/csrf_token` и сравнивается с `shared_data.csrf_token`.
Запросы без валидного токена отклоняются с `403`.

## 🚨 Сообщение об уязвимости

Если вы обнаружили уязвимость безопасности в этом проекте, выполните следующие шаги:

1. **Не создавайте публичный issue.** Свяжитесь с нами напрямую для ответственного раскрытия уязвимости.

2. **Отправьте email** на [bjorn-cyberviking@outlook.com](mailto:bjorn-cyberviking@outlook.com) со следующей информацией:

   - Описание уязвимости.
   - Шаги для воспроизведения проблемы.
   - Потенциальное влияние или степень серьёзности.

3. **Дождитесь ответа.** Мы подтвердим получение вашего сообщения и оперативно устраним проблему.
